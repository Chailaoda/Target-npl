## 实现范围

- MediaCrawler 采集仍强制直连。Web 端固定显示直连，不提供代理切换。独立 Chrome 使用 --no-proxy-server，采集 HTTP 客户端固定 trust_env=False、正常验证 TLS；该策略只作用于采集渠道。
- “处理规则”：编辑名称、标识、主题表达式、歧义回复与本地分类规则。
- “证据门槛”：逐项修改态度、意向、推广、身份的原句门槛，以及接受条件和排序分。
- “采集设置”：关键词、页数、作品和评论上限、间隔、请求额度与时限。
- “导入规则”：接受单独的 schema_version=2 规则文件，或包含 policy 与 collection 的完整规则包。导入先加载为草稿，不直接覆盖生效配置。
- “完整 JSON”：可编辑整套字段，校验并载入草稿后，再保存并应用。
- “导出规则”：下载当前完整草稿规则包，便于换方向或备份。
- “规则预览”：只执行本地规则，不触发采集或模型 API；不将本地预览写成云模型实测。
- “版本历史”：完整快照不可覆盖，可重新载入为草稿再应用。

## 保存与流水线连接

保存后将规则和采集配置写入 data/control/versions/<revision>/ 的同一快照，并原子更新 config/control-active.json 指针。旧版本文件保留，原始 profiles/music_festival_v2.json 与 config/collection.json 不被覆盖。

workflow run、workflow collect-run 和直接运行采集脚本的默认配置都会读取这套活动快照。显式指定参数仍用于选择特定文件。正在运行的任务继续使用启动时选定的快照，下一批读取新版本，避免中途规则漂移。

完整字段、枚举、正则和数值范围由后端校验；无效导入不能成为活动版本。跨窗口保存以 ETag 检查，跨进程以文件锁串行提交，防止覆盖别人较新的更改。保存期间继续编辑时，只保存提交时的版本，随后编辑留在草稿中，不被旧响应覆盖。

本地服务有 Host、Origin 和会话令牌校验，不暴露 API 密钥，不允许任意路径读写。规则预览放在有四秒时限的独立进程中，避免复杂正则阻塞服务。配置保存本身不触发采集或付费调用。
