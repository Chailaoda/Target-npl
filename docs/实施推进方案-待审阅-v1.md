## 1. 建议你审阅的核心方案

**建议做一套“通用处理引擎 + 可切换领域模板 + 本地人工复核工作台”。先用获授权的导出文件跑通，再决定平台接入。现有电脑够一期使用，无需先买显卡、服务器或云主机。**

第一版采用 Windows 原生 Python、SQLite、本地 CPU OCR 和一个模型 API。环境、缓存、数据都放在 `E:\workplace\Target-npl` 内，避免继续挤占 C 盘。

一期优先验证两个普通兴趣模板：“户外徒步组队”和“独立开发者协作”。它们用于证明换领域时不需要改处理引擎，而不是把项目固定在这两个方向。

材料中的成人亚文化个人识别部分需要改变实现方式：**不从公开评论、昵称或图片推断具体个人的性相关偏好，不生成此类个人名单。**如后续要服务涉及敏感偏好的社交场景，应采用成年人主动报名、自述、明确授权参与和可撤回的模式；不通过关键词、头像或模型猜测年龄。该分支另列需求与工期，本期先建立通用底座。

## 5. 架构与模板机制

处理链路：**数据入口 → 来源与权限检查 → 内容及关系标准化 → 按需 OCR → 质量标记 → 领域分析 → 字段与证据校验 → 人工复核 → 导出。**

底座负责文件导入、任务状态、上下文关系、存储、模型调用、证据检查和界面。领域模板负责具体“看什么、提取什么、怎样排列”。模板不能关闭授权要求、敏感个人推断限制、来源追踪或操作审计。

| 可手工调整的配置 | 示例 | 生效方式 |
| --- | --- | --- |
| 模板标识和说明 | 徒步、独立开发协作 | 新建或复制模板 |
| 主题词、别名和排除线索 | 徒步线路、编程技术栈、培训广告线索 | 编辑 YAML 后先预览差异 |
| 输出字段 | 活动区域/时间/强度；技术栈/合作角色/项目阶段 | 按字段类型和可选值校验 |
| 排序与展示 | 哪些结果优先复核、表格显示哪些列 | 下一个批次应用 |
| OCR 条件 | 正文较短、正文提示看图等 | 只处理允许使用的图片 |
| 筛选阈值 | 不同模板使用不同阈值 | 用固定样本确认质量变化 |

修改流程是“编辑 → 配置校验 → 小样本预览 → 接受新版本 → 重跑或处理新数据”。运行开始时保存整份配置快照和内容哈希，正在执行的批次不会被中途修改。文字版本号用于阅读，哈希用于确认实际规则一致。

一期支持关键词、枚举、文本、数值、列表等已约定字段。新增平台、新的复杂关系、视频理解或不同交互流程，不能仅靠改 YAML 完成。

### 数据与证据的最低要求

- 来源主键包含“平台/来源 + 对象类型 + 原始 ID”；帖子、评论和父评论保持关联，缺失上下文明确标记。
- 分开保存原始版本、OCR 结果、质量标记、模型结果、复核记录和批次记录；通用分析字段配合 `extracted_slots` JSON 保存模板专属字段。
- 每次结果绑定源内容哈希、模板哈希、Schema/提示词版本、模型标识和 OCR 版本。只有输入与相关版本均一致才复用缓存。
- 每个结论附具体原句和出处，引用须能在实际输入中找到。父评论帮助理解语境，不能把父评论作者的个人属性转给回复者。
- 相似指纹距离与出现频次分成两个参数；相似组用于去重展示或复核，不单独作为营销定罪依据。
- 原文中的命令按内容处理，不允许模型据此执行工具；界面转义外部文本；错误引用、无效 JSON 和缺来源结果进入待核队列。

SQLite 适合一期的单机、小批量、单写入者结构；使用短事务与适当索引。若启用 WAL，数据库保留在本机磁盘，备份使用一致性备份方式，不在写入时只拷贝一个 `.db` 文件。高并发或多人服务再评估迁移。[SQLite 官方说明](https://www.sqlite.org/wal.html)

### 一期建议空间预算

| 类别 | 规划额度，非实测占用 |
| --- | --- |

以约 10 万条、每条平均 3 KiB 的文本记录计算，裸文本约 293 MiB；实际数据库会叠加索引、上下文与多版本结果，不能据此直接承诺完整数据库大小。图片才是主要增量：1000 张、每张平均 1 MiB 就接近 1 GiB，因此按需处理和限额比添显卡更重要。

使用云模型时，只发送完成普通兴趣分析所需的最少文本，先遮盖不必要的身份标识与联系方式。后续自愿报名分支的敏感自述字段不默认发送到云模型。

费用建议：新增硬件和服务器预算为 0；模型试验可先设 **100 元人民币的预算上限建议**，这不是现成报价，也不代表当前发生任何付款。若数据接口收费，需单独核算，不能算进“开源免费”。

模型成本按实测用量估计：

`费用 = 输入 token 数 / 100万 × 输入单价 + 输出 token 数 / 100万 × 输出单价`

例如 1000 次调用若每次平均输入 2000 token、输出 300 token，则约为 200 万输入、30 万输出；再预留 20% 的失败重试预算。具体金额以所选服务的当日官方价格和试跑账单为准。修改语义规则或模型后，相关数据可能需重新调用 API，并非所有重跑都“免费、几秒完成”。

## 9. 验收标准与日常运转

以下是**拟定目标，不是已通过的测试结果**。P0 确认口径后执行，不以演示截图代替业务验收。

| 维度 | 一期拟定验收要求 |
| --- | --- |
| 模板通用性 | 相同底座运行两个普通兴趣模板，字段、条件、报表列和版本分别正确，不修改 Python 业务代码 |
| 数据关系 | 验收样本的来源、帖子、评论和父评论均可追溯；缺失关系进入待核，不伪造补全 |
| 证据可靠性 | 所有可展示结论均通过原文定位检查；OCR 引用能回到对应图片与识别区域 |
| 模型输出 | 所有接收入库的分析结果均通过本地 Schema 校验；无效输出不能进入通过队列，另报首次有效率 |
| 筛选效果 | 在独立验收集上，相关结果精确率目标 ≥90%、召回率目标 ≥80%，同时报告分子分母和各模板结果；样本不足时不外推承诺 |
| 权限与敏感边界 | 预置无授权、撤回、敏感个人推断等用例均被阻断；需要成年参与的报名分支另做年龄状态门禁 |
| 复核可用性 | 人工通过/驳回写入数据库，关闭工作台后可恢复；只导出静态 HTML 不算完成复核持久化 |
| 运行恢复 | 同批重跑不重复计数；中断后能识别完成/失败项；不能把部分失败写成全批成功 |
| 费用与资源 | 展示调用数、token、耗时、失败原因与占用；达到配置限额后停止新增任务并保留进度 |
| 数据恢复 | 从一致性备份恢复到独立测试位置，能查回样本和复核状态 |

标注集建议分成约 100 条开发样本和 100 条独立验收样本，按原帖分组切分，避免同一帖子上下文同时进入两边。反复用过的验收集会逐渐变成调优集，后续需要新增保留样本。只在发生相关变化或证据不足时补测，不无变化地重复全套检查。

运行初期建议单批 300–1000 条导入数据、模型并行 1–2；均为保守起点，实测后调整。真实接口的额度和限速以来源许可为准。先完成 3 天、每天一个小批次的观察，再决定是否定时执行。

默认保留期建议：获授权原始文本 30 天、图片缓存 7 天、运行元数据 90 天；具体以来源许可和实际需要为准。分析结果、人工复核及报告不得脱离源数据的删除要求长期留存。备份也需有清理期限；同盘备份仅支持误删和逻辑恢复，不作为硬盘故障灾备。

电脑睡眠或关机会影响本机任务。需要持续在线、多人访问或更大日处理量时，再评估专用机器/服务器，不在一期为此改系统设置。
