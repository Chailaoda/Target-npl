## 核心规则：按内容判断，按作者汇总，证据随结论保留

不再用一个互斥标签同时表达主题、意向和推广。后续分析结构分为独立维度：

| 维度 | 值/内容 | 用途 |
| --- | --- | --- |
| topic | relevant / unrelated / uncertain | 是否属于当前普通兴趣主题 |
| stance | positive / negative / neutral / unclear | 当前作者是否表达喜欢或排斥 |
| intent | seeking_company / planning / attended / none / unclear | 找同行、参加计划、本人参与经历分别记录 |
| evidence_level | explicit / related_only / insufficient | 明确自述与标签弱线索分别展示 |
| promotion | yes / no / uncertain | 推广作为独立标记，不能直接抹掉同帖的兴趣表达 |
| author_role | individual / organizer / unknown | 仅依据明确自述，不根据昵称猜身份 |
| evidence | 原句、起止位置、源对象 ID、上下文对象 ID | 每项维度单独挂证据，不复用一个词替代所有结论 |
| reason | 简短理由与不确定原因 | 人工核对依据，不作为原文事实 |

结果是可复核的公开账号线索，不保证身份真实性或现实参加意愿。多维结构为待实现；当前单标签分类保留作历史版本，迁移时升级 Schema/提示词/评估器版本。

## 分层处理机制

1. 原始层：保留上游原始导出文件及哈希、采集时间、关键词、来源任务、上游提交版本，不覆盖。不保存或导出 Cookie；项目登录资料仍独立保管。
2. 标准化层：统一 platform、object_type、content_id、author_id/author_url、text、url、parent_id、root_id、发布时间与采集时间；平台账号 ID 仅取公开来源，不使用昵称充当稳定主键。时间解析失败保留原始字符串与状态。
3. 关系层：帖子、评论、回复各自保留作者与原文，按源 ID 连接。父级仅帮助理解上下文；“我也是”不能直接继承父作者的兴趣属性。缺父级时标记 context_missing，不伪造关系。
4. 清洗层：清洗文本另存，与原始文本分开；保留标签、表情、否定词和原文位置映射。OCR 另存版本，仅在正文不足且图片确有必要时处理，不先下载所有视频。
5. 去重层：同平台+对象类型+源 ID 为内容身份；原文变化为新版本。不同关键词召回同条内容保留多条来源关系、只分析一次。相似文本只分组，不把不同作者合并为一个人。
6. 规则层：主题词用于召回与相关性预筛；否定、推广、歧义分别标记。标签只产生相关线索，不能单凭标签确认喜欢或找同行。参加经历可形成参与线索，不能据此推出未来参加计划。
7. 模型层：只分析未缓存、需语义处理的内容；本地校验字段、枚举、证据位置和上下文归属。上下文按需提供，禁止把帖子作者结论转移给评论者。API 只发送分析必要文本和关系角色，不发送账号或链接。
8. 质量层：坏 JSON、越界引用、缺来源、未知作者归属分别进入失败/待核对，不算零命中。不自动重试无限消耗额度。
9. 汇总层：同平台公开稳定作者 ID 汇总多条内容。明确线索与相关弱线索都可查看，不能把条数当人数；不跨平台推断同一个人。后续人工确认/驳回另表保存，不改原文和模型结果。

## 配置边界

领域模板负责：主题名称、搜索词组、别名、排除提示、分类定义、独立维度的展示/筛选条件、排序权重和样例。

采集配置负责：平台、关键词清单、每词页数/条数上限、是否采集公开评论及回复、请求间隔、任务总量上限与停止条件。代理必须仅作用于该渠道；浏览器和 HTTP 客户端均单独核验直连，不改全局配置。

系统固定机制负责：来源追踪、证据归属与位置校验、版本/缓存一致性、失败隔离、密钥保管与审计。配置不能关闭这些机制。模板不得用于推断个人敏感属性。

版本标识至少包括：来源内容哈希、模板哈希、标准化版本、分析 Schema/提示词版本、模型名/入口、上下文内容版本、OCR 版本（如使用）。上述任一分析相关内容改变才重新分析；UI 排序变化不应重新调用模型。
