## 一键运行

双击项目根目录的“运行音乐节筛选.cmd”，或在本目录执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m festival_match.workflow collect-run --mode ark --max-api-calls 40
```

采集设置：config/collection.json。领域规则：profiles/music_festival_v2.json。已有方舟连接和本机凭证继续使用，不需要再提供 API。

默认两个关键词、每词一页、每词最多五条作品、合计最多十条，每条最多三条公开评论；请求间隔三秒，最多十四次采集 API 请求，总时限一百八十秒。关闭视频、封面和图片下载，不采二级回复。分页参数支持一至三页，本轮实际仅验证每词一页，不能宣称深层分页稳定性已验收。

程序只核验并使用项目专用 Chrome；它退出时可自动恢复原隔离目录。登录或验证码须本人在该窗口完成，不自动提交凭据或处理验证码，不接管常用浏览器，不关闭用户现有浏览器。HTTP 客户端强制 trust_env=False、verify=True、不跟随跳转，专用 Chrome 使用 --no-proxy-server；系统、其他软件与模型渠道的代理设置不变。

## 规则机制

1. 原始导出不覆盖，来源文件哈希、关键词、行号、任务和固定上游版本可追溯。标准化与模型结果另存 SQLite。
2. 帖子和评论分别保存 ID、作者匿名键、正文、父评论和根帖关系。不同关键词召回同条内容保留来源关系，只分析一次；无稳定作者键时不按昵称合并。
3. 模型分别判断主题、态度、意向、推广和作者角色。每项判断挂原句、位置与来源。仅主题相关性可以引用父级上下文；态度和个人意向证据必须出自当前作者，歧义短回复不能继承父作者观点。
4. 本地 decision_gates 再核对具体语义线索。例如“一个人”不足以证明找同行，“定闹钟等开票”不足以证明已经参加，泛泛赞美和歌曲名不直接当作个人喜欢音乐节。弱线索始终保留，不用过滤掩盖召回结果。
5. 模型分类缓存与本地决策分离。修改具体证据门槛、接受条件或排序，不重新调用模型；主题、分类定义、模型、分析器版本或上下文改变才失效。旧缓存迁移须逐条重验原文引用与上下文，不能直接沿用错误版本。
6. 无效模型 JSON/枚举/证据不采信，隔离为待复核并保存调用用量，不冒充未命中，也不自动重试。网络等执行故障保留为失败；连续故障有停止保护。原模型维度与本地降级理由分别保存在 JSONL 中。
7. 历史作品发布时间明确展示；帖子中的计划和邀请不代表现在仍然有效，不从旧时间推断当前意愿。

所有决策规则均在领域配置中，不写死在 Python 的音乐节分支中。更换普通兴趣方向时，调整采集关键词、主题词、证据规则、接受条件和排序。
