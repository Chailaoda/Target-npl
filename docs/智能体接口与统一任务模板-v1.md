# 统一筛选任务与智能体接口 v1

日期：2026-10-30，America/New_York。本文为当前入口；旧版两层配置仍兼容，但不要求使用者分别填写。

## 已落地的工作方式

自然语言目标 → 基于当前人工版本制定字段级变更 → 校验能力/规则/额度 → 原子保存统一版本 → 后台执行 → 查询真实结果 → 人工继续微调。

统一任务包包含三个部分：

| 字段 | 内容 |
| --- | --- |
| task | 目标说明、活动地点、时间范围、排除条件、执行来源/模式/额度、假设、未解决项、人工锁定字段 |
| policy | 主题、判断规则、具体原句门槛、接受条件与排序 |
| collection | 平台关键词、有限分页、作品/评论上限、频率、请求数与时限；固定直连 |

三部分存于同一个不可变版本，Web 和智能体读取相同配置。task.schema_version 为 1，policy.schema_version 为 2。严格字段 Schema 在 schemas/screening-task-v1.schema.json，工具参数表在 schemas/agent-tools-v1.json。

## 智能体接入

提供 stdio MCP 和命令行，两者调用相同 TaskService，不依赖浏览器操作。

- MCP 入口：scripts/task_mcp.py。
- 客户端配置示例：config/mcp-client.example.json，已写本机绝对路径，不包含 API 密钥。
- 没有擅自修改 Codex 或其他软件的全局 MCP 注册/权限设置。把配置示例加入需要接入的客户端后，客户端可以发现这些工具；当前会话也可以直接使用命令行接口。

| 工具 | 作用 |
| --- | --- |
| screening_capabilities | 先查询真实支持范围，不假装平台有原生地域/时间过滤 |
| screening_task_get | 读取当前人工版本、统一任务包、revision 和 ETag |
| screening_task_submit | 一次目标自动制定、校验、应用并启动；关键问题返回 needs_attention |
| screening_task_plan | 只制定草稿，返回变更、假设、待解决项与模型用量，不应用或执行 |
| screening_task_validate | 校验完整任务及调用额度 |
| screening_task_apply | 用 base_etag 应用完整任务，拒绝过期版本及人工锁定冲突 |
| screening_task_patch | 用标准 JSON Patch 微调具体字段，仍遵守锁定和额度 |
| screening_datasets | 查看可复用的真实采集批次 |
| screening_task_run | 按明确 revision 执行，request_id 用于防止重复启动 |
| screening_task_status | 查询真实执行状态、阶段和结果摘要 |
| screening_task_results | 分页读取原文、证据及任务范围检查结果 |

推荐智能体流程：读取 capabilities 和 task_get；如果用户已授权推进，在预设额度内直接调用 task_submit；随后用返回 run_id 查询状态及结果。无需每次再要求人工确认配置。只在待解决条件、登录/验证码、人工锁定冲突或超过额度时停止受影响动作。

也可以按 plan → validate → apply → run 分步调用。每次都以最新 ETag 为基准，不能拿历史版本覆盖人工刚改的内容。

submit 请求示意：

```json
{
  "goal": "帮我找最近想去成都音乐节、正在找同行搭子的人，排除卖票和推广留言。",
  "base_etag": "从 screening_task_get 读取",
  "request_id": "chengdu-festival-20261030-001"
}
```

同一个请求重试时，goal、base_etag、request_id 均保持原值。已有提交日志会直接返回，不重复调用规划模型或启动任务。不要把同一个 request_id 用于另一个目标。执行接口也按明确版本和 request_id 幂等。

命令行形式：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m festival_match.task_agent call --tool screening_task_get
.\.venv\Scripts\python.exe -X utf8 -m festival_match.task_agent call --tool screening_task_submit --arguments-file 你的提交参数.json
.\.venv\Scripts\python.exe -X utf8 -m festival_match.task_agent run-active --wait
```

项目“运行音乐节筛选.cmd”现调用统一任务入口，按已保存任务的数据来源、分析方式和额度执行。默认选择复用已有数据；需要新增采集时在 Web 或任务配置中明确选择。低层 workflow 命令保留兼容，并能读取对应快照中的 task.json；显式参数按运行参数记录。

MCP 实现采用官方 stdio 的逐行 UTF-8 JSON-RPC、initialize、tools/list 和 tools/call；stdout 只输出协议消息。[官方传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)、[官方工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。这里的 Web HTTP API 是应用接口，不冒充 Streamable HTTP MCP。

## Web 端

地址仍为 http://127.0.0.1:8766 。更新后刷新页面，进入“任务目标”：

- 输入目标后，“生成任务配置”只生成可检查、可修改的草稿。
- “自动配置并执行”在已有授权额度内完成制定、保存和启动，不再分别填两层配置。
- 如果先人工修改了规则，需要先保存，再从新版本制定下一目标。
- 原有“处理规则、证据门槛、采集设置、完整 JSON、版本历史”继续编辑同一任务包。
- “人工修改保护”展示锁定路径，人工可以解除相应字段锁定。
- 从智能体草稿微调再保存时，只把人工实际改变的字段记为人工锁定，不把全部自动生成字段误锁定。

界面继续使用 MediaCrawler 现有设计变量和组件；未改变采集直连策略。Web 和 MCP 不会导出 Cookie、查询其他软件凭证或联系目标账号。

## 条件如何真正生效

- 关键词：交给 MediaCrawler 搜索，仅为召回。
- 活动地点：在本人正文或关联原帖中匹配地点词；不当作作者所在地、常住地或 GPS 位置。
- 最近天数：按当前对象自己的发布时间和任务创建时间检查。缺失则标记范围待核对，不能用父帖时间冒充评论发布时间。
- 绝对起止日期：按 UTC 日期检查，字段接受 YYYY-MM-DD。任务创建后截止基准固定，导出不会随当天变化漂移。
- 推广排除：按通过证据门槛后的推广维度处理；推广状态不确定时保留范围待核对，不直接断言已排除。
- 字面排除词：只检查当前作者正文，不从父帖继承卖票/推广身份。
- 范围不符和范围未知都不能进入明确候选；报告分别显示范围不符/排除、范围待核对。
- 不支持的明确要求保留在 unresolved，不能自动执行。非关键默认值，例如“最近=30天”“未指定某场则覆盖成都相关音乐节”，放 assumptions，不要求重复确认。

当前接口不会提供“平台已完成地域/时间过滤”的假能力。也不新增跨平台身份关联、个人敏感属性推断或匿名身份还原。

## 版本、并发及额度

人工普通保存会记录实际改变的字段。智能体必须基于最新 ETag，且不能改变 human_overrides 中锁定的值或删除锁定标记。只有 Web 人工操作可以解除锁定。正在运行的批次使用启动时冻结的请求与模板，新修改只影响下一批。

智能体不能自动提高预设模型调用上限、采集页数/数量/请求上限，或提高采集频率。新增采集的最大内容量也必须在本批模型额度内。超过预设返回明确错误，不能先调用再让用户补批。

每个后台任务绑定 request_id、配置版本、完整任务快照、源文件哈希、分析批次、报告路径与用量。相同输入的模型分析可以复用；地域/时间/排除项是后处理条件，不必为同一正文重复调用模型。
