## 用户最后需要做的事

1. 刷新 http://127.0.0.1:8766/ ，进入“任务目标 → 平台接入与选择”。这里可勾选七个平台；页面加载和全选只改草稿，不自动打开浏览器或采集。
2. 在准备好时逐个平台点“打开登录窗口”，在相应专用直连 Chrome 中本人登录/处理验证码。登录窗口打开不自动开始采集，界面不读取展示密码或 Cookie。不要七个平台同时登录，便于识别窗口。
3. 切换目标方向时核对关键词、主题、数据来源。要新增数据选“新增有限采集”。先对各平台逐个做小规模真实验收，再启动多平台批次；当前不预设它们均可正常在线抓取。
4. 希望全平台进行首轮有限采集，可在“导入规则”载入项目 `examples/七平台基础采集任务-v1.json`。这是当前目标的备用整包，不自动生效；核对后保存并执行。它设置整个任务最多 7 条作品、每作品 1 条一级评论、50 次 API 请求、600 秒总采集时限、40 次分析调用上限。不是每个平台各 7 条作品或各 40 次模型调用。
5. 运行台显示当前平台、各平台状态、带来源标记的数据流；所有平台完整采集后才进入统一分析。完整报告按内容显示平台。遇到部分失败或待登录，保留检查点并停止自动分析，不把部分数据包装成全平台成功。

默认保持原有活动任务。单击“全选七个平台”不会自动提高额度；原来较低的请求上限可能不足以读七个平台的登录检查、详情和评论。调整上限或导入首轮预设均需人工保存，智能体不能自行突破原有授权上限。

## 接口与命令

MCP 现有任务工具保持兼容，新增：

- `screening_platforms {}`：只读平台目录，`browser_configured` 不代表登录有效，`login_status=not_verified`。
- `screening_platform_login {"platform":"xhs"}`：只有用户准备登录时调用；仅打开该平台专用直连窗口，不启动采集。

MCP 工具共 13 个，当前机器定义见 `schemas/agent-tools-v1.json`。原 get/plan/validate/apply/run/status/results 等流程继续使用。

```powershell
Set-Location -LiteralPath 'E:\workplace\Target-npl'
# 只读目录，无登录或抓取动作
.\.venv\Scripts\python.exe -X utf8 -m festival_match.task_agent platforms
# 以下命令留给本人准备登录时执行
.\.venv\Scripts\python.exe -X utf8 -m festival_match.task_agent open-login --platform xhs
```

统一任务保持 `{task, policy, collection}`。`collection.platform` 为主平台；可选新增 `collection.platforms` 数组选择多个平台，主平台必须包含在数组中。旧配置没有 platforms 时只运行 platform，兼容旧抖音快照。智能体指定平台时同时更新两个字段，仍遵守 ETag、人工锁定和额度保护。

## 运行机制与边界

- 各平台串行执行，共享总作品数、总 API 请求数与采集时限，按剩余额度分配；模型分析只启动一次，仍遵守原有任务调用上限。浏览器页面资源加载不等同采集 API 计数。
- 登录资料隔离在 `cache/<platform>-browser`，元数据为 `cache/<platform>-browser-session.json`。没有登录配置的新平台直接返回待本人登录，不在后台自动登录。
- Chrome 固定 `--no-proxy-server`；采集 HTTP 固定 trust_env=False、正常 TLS 验证、不跟随跳转。贴吧复用上游浏览器内请求，并加入请求额度与间隔检查。系统代理、其他软件与方舟模型网络配置不变。
- 只采集搜索作品、必要详情和有上限的一级评论。不采集个人主页、粉丝、私信或媒体文件，不自动互动，不关联跨平台身份。各平台界面不一定逐条点击视频。
- 保存平台标识、作品/评论关系、原文和自身发布时间；丢弃登录/验证 token、真实用户 ID、昵称、媒体与个人资料字段，保留上游匿名哈希。链接移除查询参数，小红书链接若需要平台校验，应由本人在已登录页面访问，不在报告保存验证 token。
- 毫秒/秒时间戳和带时区时间可标准化；相对时间或缺少明确时区的文字时间保留未知，不套用父帖时间，不假装满足“最近”条件。
- 新平台的部分采集保留原始子批次和失败原因，当前不提供自动跨平台续采重试。不要直接重跑同 request_id 的失败任务期待恢复；排查后由用户授权新批次，已有分析仍可按缓存复用。
- 合并批次是复用数据的正式入口；子批次不重复列为“最近完整采集”，避免 latest 只读最后一个平台或重复计数。

离线测试使用虚构数据和 MockTransport，不能替代真实平台验收；本轮未绕过此前浏览器访问权限限制进行视觉验收。上游源码保持固定版本，许可继续适用。
